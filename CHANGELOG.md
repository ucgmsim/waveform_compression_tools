# Changelog

## 1.2.0

- **An HF.bin converter,** `convert-hfbin`, and `read_hfbin` and `convert_hfbin` in Python, beside `convert-bbbin`. It keeps the acceleration in cm/s², as stored, and every field of the header as an attribute in its own type. A file that isn't an HF.bin is refused with `NotHFBin`, as is one cut short by a run that stopped early, whose error line adds `or one cut short`. A full-size file that its run left unfinished, with a station's `vs` of 0, is refused with `IncompleteHFBin`. Both exit with status 3.
- **convert-bbbin takes less memory, and its refusals say more.** It reads the traces a block of stations at a time, so converting a synthetic BB.bin of 0.36 GB peaked at 0.54 GB of resident memory, where 1.1.0 took 0.83 GB. A file shorter than its header says, which holds the whole header and every record, is refused with a line that adds `or one cut short`. A name or a string with a NUL inside it, and a file that shrinks while it is read, are refused with `NotBBBin` and status 3, with a line that names SRC, where 1.1.0 failed with status 1 and a line that named DST. Every refusal's message now starts with the file, so its line names the file once, as `BB.bin: not a BB.bin file (2000 bytes)`; 1.1.0's line named it twice, as `BB.bin: not a BB.bin file: BB.bin (2000 bytes)`. HF.bin's refusals are worded the same way.
- **`open_dataset` reads a few stations of a big file.** `waveform_compression_tools.open_dataset(path)` opens a compressed file as the dataset that `decompress_file` gives, but decodes its waveform only where it is read. Selecting with `sel` or `isel` reads nothing, and reading a selection reads and decodes only its traces, bit for bit as `decompress_file` gives them. A selection of points, such as one component at each of several stations, decodes every chosen component of every chosen station. It is `xr.open_dataset(path, engine="waveform_compression_tools")`, xarray's way to open a compressed file. On a synthetic file of 12,000 stations of 39,629 samples, 2.9 GiB at 24 bits, opening it and reading 3 stations took 0.05 to 0.06 s, and resident memory peaked at 115 MB. On one of a million stations of 16 samples, it took 0.5 s, and memory peaked at 335 MB. Of each peak, 103 MB was Python and the packages it had imported.
- **decompress writes a block of stations at a time,** so a file of any size can be decompressed, and its memory doesn't grow with the file. On synthetic files of random walks it peaked at 0.34 GB of resident memory for 3.5 GiB of waveform, and at 0.35 GB for 10.6 GiB; 1.1.0, which held the whole waveform, peaked at 3.96 GB for the first. `decompress_to` does the same, and writes the same file as before, but for how HDF5 lays it out; it now returns the waveform's shape. A full disk or a Ctrl-C stops it at the end of its block, as in `compress`. `decompress_file` still returns the whole dataset in memory.
- **verify and decompress read only each block's own streams,** whatever blocks the file was compressed in. A block used to read everything from its first stream to its last, which takes in other blocks' streams when the file was compressed in other blocks, as with `block_stations`: for a file compressed in one block, most of the file.
- **A damaged compressed file raises `Damaged`, which names it.** It is a `ValueError` whose `filename` is the file, raised by `decompress_file`, `decompress_to`, `verify_file` and `open_dataset`'s reads. Before, a stream that didn't decode, or decoded to the wrong number of samples, raised a `ValueError` that named no file; a part of the format that the file lacked raised h5py's `KeyError`, and one that couldn't be read, as JSON that didn't parse or wasn't an object, or a value outside its type's range, a `ValueError`, a `TypeError`, an `AttributeError` or an `OverflowError`; and streams that didn't fit the file's dimensions were left to xarray, whose `ValueError` of conflicting sizes named no file either. Now every way in checks that fit itself. The command line's error line names SRC, and its status stays 1.
- **A file that can't be read is named in its error, one cut short included.** HDF5's errors, as for an HDF5 file cut short, name no file. `decompress_file`, `decompress_to`, `verify_file`, `open_dataset`, `check_compressible` and `compress_file` now raise them again as an `OSError` whose `filename` is the file, with the same words. So `verify` of an ORIGINAL cut short names ORIGINAL, where 1.1.0 named COMPRESSED, and an HDF5 error while `compress` writes DST names DST, where 1.1.0 named SRC.
- **verify says when all but the samples differ.** A file whose variables, coordinates or attributes differ from its original's fails, however small its error, and its line now says so: `doesn't agree with ORIGINAL: its variables, coordinates or attributes differ (largest error … of a trace's peak)`. In 1.1.0 the line gave only the error, which read like a pass. `VerifyResult` has the new field `same_besides_samples`.
- **compress refuses a boolean waveform attribute,** with `NotStandardLayout` and status 3, before anything is written. h5py writes one, but no netCDF file holds one, so its compressed file couldn't be decompressed: in 1.1.0, decompress failed with xarray's `TypeError` and status 1, naming DST.
- **compress refuses a waveform with no components or no samples,** with `NotStandardLayout` and status 3, as it refuses one with no stations. In 1.1.0 it failed with `ZeroDivisionError` and status 1.

## 1.1.0

The file format is unchanged, at version 1: 1.0.0 reads the files that 1.1.0 writes, and 1.1.0 reads 1.0.0's.

- **A small file is made smaller too.** 1.0.0 kept the streams in chunks of 4 MiB, or of the waveform's size if that was smaller, and HDF5 keeps every chunk whole, however little of it is filled. So a file whose waveform was under 4 MiB came out no smaller, and a bigger one held up to 4 MiB more than its streams needed. Now the streams of a file compressed in one block, which holds up to about 128 MiB of waveform, are kept in exactly their size: the 2.6 MiB of LF traces in `tests/real_traces` come out 9.3× smaller at 24 bits, where 1.0.0 left them a little larger. A file compressed in more blocks keeps its streams in chunks of 1 MiB, or of the first block's streams if those are smaller, and so holds less than 1 MiB more than they need.
- **The record names the FLAC level,** as `level`, after `bits`, so `record_version` is 2.

## 1.0.0

The first release: the FLAC codec for float32 waveforms in netCDF files, as a package of its own. The file format is unchanged: the group `_flac_compressed_waveform`, at format version 1.

- **A package of its own,** `waveform_compression_tools`, installed from a release tag, with the command `waveform-compression-tools`.
- **The waveform's encoding is kept:** its `_FillValue` and `missing_value`, in the new group attribute `waveform_encoding`, and its attributes' types, in `waveform_attr_types`.
- **The waveform's attributes are strict JSON:** in `waveform_attrs`, a float that isn't finite is the string `"NaN"`, `"Infinity"` or `"-Infinity"`, which its type in `waveform_attr_types` makes a number again, so any JSON parser reads them.
- **Blocks follow a memory budget,** `BLOCK_BYTES` (128 MiB), in whole station chunks of the file unless those would exceed the budget by more than a quarter.
- **compress checks its output in the same pass,** against the samples it read, and then the closed file against its original. `--no-check` or `check=False` leaves the check out.
- **Refusals and failures have their own types:** `Refused` and its subclasses for an input that can't be used as it is, and `CheckFailed` for an output that fails the check. Neither leaves a new file at the destination; a file already there stays as it was.
- **A content hash and a per-file record:** `compress --record PATH` writes a JSON record of the run, with the input's and the output's content hashes.
- **The command line's exit codes are published:** 0 when it did its work, 1 when the run failed, 2 for a usage error and 3 when an input is refused. A failure or a refusal is one line that names the file. A file already at a destination is replaced only with `--overwrite`.
- **A full disk or quota fails the run with its own reason,** naming the output, and `compress` stops at the end of the block it was writing. HDF5 writes each output through `destinations.HDF5Output`, a file object that never tells it a write failed: a workaround for an HDF5 bug, whose own error would hide the system's, and after which HDF5 2.0.0 to 2.2.0 can crash Python. While a file is written, Ctrl-C, and SIGTERM where Python handles it, wait until they are safe to act on: until the end of the block for `compress`, and until the file is written for `decompress` and `convert-bbbin`. Sent again, either ends the run at once.
- **Memory:** on a synthetic 36.4 GiB file of random walks, 82,000 stations of 39,629 samples, compress at 24 bits peaked at 0.74 GB of resident memory, and made the file 1.8× smaller in 6 minutes. verify peaked at 0.76 GB.
